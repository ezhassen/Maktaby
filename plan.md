# DesktopBoxes — Plan

## Vision
DesktopBoxes is a lightweight, always-running Windows desktop application that organizes
desktop shortcuts, files, folders, and other desktop items into movable/resizable visual
groups called **Boxes** (never "Fences"). Each Box aggregates many items in a single
window/control. The app must be low on idle CPU and reasonable on memory because it runs
continuously in the background.

## Current Status
This repository is the **foundation only**. The project builds, runs, and shows a single
WPF window that can create placeholder Boxes. None of the real product behavior
(desktop discovery, icon extraction, drag/drop, persistence, Explorer integration) is
implemented yet. All platform code is isolated behind interfaces so it can be filled in
later without touching the Core or the UI.

## Architecture (layering)

```
Core            Pure .NET. No WPF, no Win32, no Shell. Models + interfaces + in-memory services.
  Models        Box, BoxItem, BoxItemType, geometry (RectD/PointD/SizeD), change types.
  Interfaces    IBoxService, ISettingsService, IDesktopService, IShellItemService,
                IShellIconService, IFileSystemService, plus platform abstractions
                (IMonitorService, IDpiService, IWindowPositioningService, IZOrderService,
                IDesktopWindowService, IExplorerDesktopService).
  Services      In-memory stubs: BoxService, SettingsService.

Shell           Windows Shell specific. Uses IShellItemService etc. Native Shell COM interop
                is deferred; constants live under Interop/ already.
  Services      ShellItemService, ShellIconService (stub), DesktopService, ExplorerDesktopService (stub).
  Interop       ShellWindowClasses constants; Shell COM native decls go here later.

Win32           Raw Win32. All P/Invoke isolated via CsWin in NativeMethods/Win32Apis.
  NativeMethods NativeMethods.txt + Win32Apis partial class (generated by CsWin32).
  Services      MonitorService, DpiService, WindowPositioningService, ZOrderService, DesktopWindowService.

Views/Controls/Converters/Resources   WPF only. MainWindow hosts Box controls; BoxControl is
                the reusable Box visualization; converters and resource dictionaries keep
                presentation separate.

App.xaml(.cs)   Composition root: builds Microsoft.Extensions.DependencyInjection container,
                registers Core + Win32 + Shell services behind Core interfaces, shows MainWindow.
```

## Key design rules
1. Core never references WPF, Win32, or Shell APIs directly.
2. Native declarations live only in `Win32/NativeMethods` (CsWin32). No P/Invoke in ViewModels/Views.
3. Platform behavior is exposed through Core interfaces so the UI framework could later be
   swapped without rewriting logic.
4. One control per Box; a Box contains many item controls. Never a window per BoxItem.
5. Prefer event-driven designs (DPI/monitor/Explorer change events, filesystem watches) over polling/timers.
6. Minimal NuGet surface: only `Microsoft.Extensions.DependencyInjection` and `Microsoft.Windows.CsWin32`.

## Build / run
- `dotnet restore`
- `dotnet build` (Debug or Release)
- Run `DesktopBoxesUI` (WinExe). A dark window appears with a "New Box" button.

## Implementation roadmap (future work)
Ordered, incremental phases. Each phase keeps existing layers stable.

1. **Desktop discovery** — flesh out `IDesktopService`/`DesktopService` using real Explorer
   desktop enumeration (Progman/WorkerW/SHELLDLL_DefView) instead of the plain directory scan.
2. **Box creation & positioning** — use `IWindowPositioningService`/`IZOrderService` to place
   Box windows relative to the desktop; add borderless, movable, resizable behavior in `BoxControl`.
3. **Icon extraction** — implement `IShellIconService` (SHGetFileInfo / image factory) with
   caching and lazy loading; add an `IValueConverter`/async loader for `ImageSource`.
4. **Drag & drop** — move items between Boxes and to/from the desktop; update `BoxItem` order/position.
5. **Desktop synchronization** — respond to Explorer restarts (`IExplorerDesktopService`),
   monitor changes (`IMonitorService`), DPI changes (`IDpiService`), desktop changes
   (`IFileSystemService` watches), and reconcile Box contents.
6. **Persistence** — replace in-memory `BoxService`/`SettingsService` with JSON/settings file
   load/save; restore Boxes on startup, persist on shutdown and on change.
7. **Performance hardening** — icon cache size limits, throttled layout updates, no busy loops,
   low-allocation data binding, proper COM/Shell object lifetime.

## Open questions for later
- Single top-level window hosting many Box controls vs. one native borderless window per Box.
  Current foundation uses a single MainWindow hosting Box controls (simplest, fewest windows);
  the Win32 services already allow migrating to per-Box native windows if needed.
- Exact persistence format and roaming behavior.
- Whether to enable trimming/Native AOT after WPF/COM/Win32 compatibility is verified (currently off).
